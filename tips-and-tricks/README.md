## 🎯 Interview Day Tips

| # | Tip | Priority |
|---|-----|----------|
| 1 | ✅ Join 5 minutes early, not 15 | ⭐⭐⭐ |
| 2 | ✅ Keep water bottle and pen-paper ready | ⭐⭐ |
| 3 | ✅ Test your mic, camera, internet before call | ⭐⭐⭐ |
| 4 | ✅ Think out loud — explain your thought process | ⭐⭐⭐⭐⭐ |
| 5 | ✅ Ask clarifying questions before jumping to code | ⭐⭐⭐⭐⭐ |
| 6 | ✅ Start with brute force, then optimize | ⭐⭐⭐⭐ |
| 7 | ✅ Test your code with edge cases | ⭐⭐⭐⭐ |
| 8 | ✅ Don't panic if stuck — talk about your approach | ⭐⭐⭐⭐⭐ |

## 💻 Coding Tips

| # | Tip |
|---|-----|
| 1 | 🔹 Always consider edge cases: empty input, single element, negative numbers |
| 2 | 🔹 Use meaningful variable names even in interviews |
| 3 | 🔹 Comment your approach before writing code |
| 4 | 🔹 Time complexity matters — always mention Big O |
| 5 | 🔹 Know your language's built-in methods well |
| 6 | 🔹 Practice writing code on paper/whiteboard |
| 7 | 🔹 Learn to dry-run your code step by step |

## 📝 Resume Tips

| # | Tip |
|---|-----|
| 1 | 📌 Keep it 1 page (2 max for 5+ years experience) |
| 2 | 📌 Use action verbs: Built, Designed, Implemented, Optimized |
| 3 | 📌 Add quantifiable results: "Reduced load time by 40%" |
| 4 | 📌 Match keywords with job description |
| 5 | 📌 Projects > Certificates (show, don't tell) |
| 6 | 📌 No spelling mistakes — proofread 3 times |

## 🤝 Communication Tips

| # | Tip |
|---|-----|
| 1 | 🗣️ Use STAR method for behavioral questions |
| 2 | 🗣️ Don't ramble — keep answers 1-2 minutes |
| 3 | 🗣️ It's OK to say "I don't know, but here's how I'd approach it" |
| 4 | 🗣️ Show genuine enthusiasm about the role/company |
| 5 | 🗣️ Ask thoughtful questions at the end |

## 🚀 Career Growth Tips

| # | Tip |
|---|-----|
| 1 | 📈 Build in public — share your learning journey |
| 2 | 📈 Contribute to open source |
| 3 | 📈 Network with people in your target role |

| 5 | 📈 Learn system design early — it compounds |

## 🧠 Learning Tips

| # | Tip |
|---|-----|
| 1 | 📚 Feynman Technique: Teach it to learn it |
| 2 | 📚 Spaced Repetition: Review at intervals (1d, 3d, 7d, 30d) |
| 3 | 📚 Active Recall > Passive Reading |
| 4 | 📚 Build projects to solidify concepts |
| 5 | 📚 80/20 Rule: Focus on high-frequency topics first |

## ⏰ Productivity Tips

| # | Tip |
|---|-----|
| 1 | ⚡ Pomodoro Technique: 25 min focus + 5 min break |
| 2 | ⚡ Block distracting websites during study |
| 3 | ⚡ Study in the morning — peak brain performance |
| 4 | ⚡ Track your progress daily |
| 5 | ⚡ Don't multitask — deep work > shallow work |

## 💰 Salary & Negotiation Tips

| # | Tip |
|---|-----|
| 1 | 💵 Research market salary on levels.fyi, Glassdoor |
| 2 | 💵 Never give a number first — let them make an offer |
| 3 | 💵 Negotiate total compensation (base + bonus + stocks + benefits) |
| 4 | 💵 Always get the offer in writing |
| 5 | 💵 It's OK to ask for time to think |

## 🐛 Debugging Tips

| # | Tip |
|---|-----|
| 1 | 🔍 Read the error message carefully — it tells you everything |
| 2 | 🔍 Reproduce the bug consistently first |
| 3 | 🔍 Use console.log/print strategically |
| 4 | 🔍 Rubber duck debugging: explain the problem to someone/something |
| 5 | 🔍 Check recent changes first — what did you change last? |
